# 交给 Codex 的操作步骤和提示词

## 一、准备仓库

1. 解压 `ai-friend-web-repo.zip`。
2. 在 GitHub 新建一个公开仓库，把解压出的**文件夹里面的全部内容**上传到仓库根目录，让 `index.html`、`AGENTS.md` 都在最外层。
3. 在 Codex 中选择这个仓库。

## 二、主提示词（复制整段发给 Codex）

```
请先完整阅读仓库根目录的 AGENTS.md 和 docs/TASK.md，然后按 TASK.md 完成这次网页改版。

按以下三个阶段做，每完成一个阶段提交一次：

1. 数据与结构：按 TASK.md 第4节更新 data/data.js；按第3节把页面调整为12屏（新增 #verdict，删除第12题的图表，按发布的问卷对调第14、15题，第10题改为均分点图）；更新大数字、图注编号和右侧圆点导航。
2. 视觉与排版：按第2节"三种字迹"的方向，重做颜色、字体和排版，包括页边竖排朱批、图表样式和第8屏的关系示意图。
3. 词云与发布：按第5节实现可点击的原话词云；按第6节整理成可用 GitHub Pages 发布的结构，并更新 README.md。

要求：
- 不要改写或新增论述文字，只按 TASK.md 列出的地方修改；没有给出原文的地方，保留或新增【……】占位。
- 同学原话必须逐字照抄。
- 完成后按 TASK.md 第7节逐项自检，并在回复里列出：修改了哪些文件；1366×768 下每一屏是否完整显示；页面上剩余的全部【……】占位；你没能完成或拿不准的地方。
```

## 三、检查成品

1. 双击 `index.html`，按 ↓ 逐屏看一遍，或者开启 GitHub Pages 后在线看。
2. 对照 Codex 回复里的自检结果，重点核对：数字是否正确，同学原话有没有被改动，1366×768 下有没有内容被挤出屏幕。
3. 有问题时，用下面的"修改反馈模板"让 Codex 改。

## 四、修改反馈模板

```
请修改第X屏（#id）：
现在的问题：……
希望改成：……
不要改动其他屏，也不要改动任何文字内容。改完后截图确认 1366×768 下这一屏完整显示。
```

## 五、填文字（小组写好 docs/COPY.md 之后）

```
请按 docs/COPY.md 中小组填写的内容，替换页面上对应的【……】占位。
- 只替换占位，不要修改、润色其他任何文字；COPY.md 里留空的项保持占位不变。
- 标了"保留 / 删除"的可选内容（14号原话批注、23号原话批注、结尾的第十一条题记），按 COPY.md 的选择保留或删除，并删掉对应的 HTML 注释。
- 如果 COPY.md 修改了小标题，同步更新 data-title 和圆点标签。
完成后列出替换了哪些地方、还剩哪些占位，并确认 1366×768 下每一屏仍然完整显示。
```

## 六、如果一次做不完

Codex 中途停下或结果太乱时，可以把三个阶段拆成三次发送，每次都以这句开头：

```
请先阅读 AGENTS.md 和 docs/TASK.md。
```

然后分别接：

- 阶段1："这次只做数据与结构：TASK.md 第3、4节。不要改视觉样式。"
- 阶段2："这次只做视觉与排版：TASK.md 第2节，以及第3节里各屏的排版要求。不要改数据和文字。"
- 阶段3："这次只做词云和发布：TASK.md 第5、6节，最后按第7节自检。"

## 七、开启 GitHub Pages

仓库 Settings → Pages → Build and deployment → Source 选择 "Deploy from a branch"，Branch 选 `main`、文件夹选 `/ (root)`，保存。几分钟后可以通过 `https://<用户名>.github.io/<仓库名>/` 访问。
